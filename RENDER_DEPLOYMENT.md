# Eco-Point — Render + PostgreSQL migration

**Status: staging code, not production cutover.** The live Hatchable website and database remain untouched. Firebase is not used.

## Architecture

One Render Node.js service serves the existing static frontend, 20 API endpoints, member email-code login, and admin sessions. Render Managed PostgreSQL stores application records and small private image uploads with signed expiring URLs. The frontend and backend have the same origin.

Migration branch: migration/render-postgres.

## Deployment

1. Connect the Render app to ChatGPT, or open Render Dashboard > New > Blueprint.
2. Select GitHub repository khabenassaif/ECO-POINT-8 after reviewing and merging this branch into main. The Blueprint file is render.yaml at repository root.
3. Confirm the Render plan and pricing (these are paid persistent resources) before creating anything.
4. Configure protected environment variables INSIDE RENDER, not in GitHub:
   - ADMIN_ACCESS_CODE: NEW secret of at least 12 characters; previously exported verifier is not reused.
   - SMTP_HOST, SMTP_USER, SMTP_PASSWORD, EMAIL_FROM, optionally SMTP_PORT.
   - DATABASE_URL comes from Render Postgres and SESSION_SECRET is generated by Render.
5. Deploy and verify /healthz and application logs. The server applies tracked SQL migrations and seeds default categories and rewards.

## Preserved workflows

Member dashboard, profile, reporting with GPS/photo and automatic checks; private media, leaderboard and notifications; admin code authentication, report review and atomic point awards; reward management, redemption, vouchers and Spin Wheel.

## Caveats

- Email-code login requires SMTP. Google OAuth and passkeys are deliberately disabled and not represented as working.
- Private media currently uses PostgreSQL bytea. A durable object store should replace this at higher upload volumes.
- Existing Hatchable users, personal data, and stored images are NOT migrated by these GitHub changes. Export and reconcile them privately before a production cutover.
- The bootstrap skips Hatchable-specific policy migration 0011 and strips the old exported admin verifier from migration 0008.
- GitHub Pages serves only static files and is not the target of this full-stack deployment.
- A deployment cannot be called complete until the Render service exists and the endpoints are tested.
